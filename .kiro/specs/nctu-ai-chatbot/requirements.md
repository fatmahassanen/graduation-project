# Requirements Document: NCTU AI Chatbot

## Introduction

The NCTU AI Chatbot is an intelligent multilingual conversational assistant designed to serve as both an academic advisor and marketing representative for New Cairo Technological University. The system provides contextually aware responses about university navigation, admissions, academic programs, and student services while operating bilingually in Arabic (including Egyptian slang) and English. The chatbot includes built-in safeguards against jailbreak attempts and hallucination prevention for dynamic information such as dates and deadlines.

## Glossary

- **Chatbot_System**: The complete AI-powered conversational assistant including backend services, AI integration, and frontend widget
- **AI_Client**: The service component that communicates with external AI providers (OpenAI or Gemini)
- **System_Prompt**: The comprehensive instruction set injected into AI requests containing navigation structure, marketing content, and behavioral directives
- **Prompt_Builder**: The service responsible for constructing the system prompt from various content sources
- **Chat_Widget**: The frontend JavaScript component that provides the user interface for chatbot interaction
- **Conversation_History**: The sequential record of user and assistant messages within a session
- **Navigation_Map**: The structured representation of the university website's navigation hierarchy
- **Marketing_Content**: The collection of university value propositions and promotional messages
- **Hallucination**: When an AI generates false or unverifiable information, particularly regarding dates and deadlines
- **Jailbreak_Attempt**: User input designed to manipulate the AI into breaking character or performing unauthorized actions
- **Language_Detection**: The process of identifying whether user input is primarily Arabic or English
- **User_Message**: Text input submitted by a user through the chat interface
- **AI_Response**: Text output generated by the AI service in response to user input
- **Session**: A temporary user interaction context that stores conversation history
- **CSRF_Token**: Cross-Site Request Forgery protection token required for POST requests
- **Rate_Limit**: Maximum number of requests allowed per user within a time window

## Requirements

### Requirement 1: Message Processing and Response Generation

**User Story:** As a user, I want to send messages to the chatbot and receive intelligent responses, so that I can get information about the university.

#### Acceptance Criteria

1. WHEN a user submits a valid message, THE Chatbot_System SHALL process the message and return an AI-generated response
2. WHEN processing a message, THE Chatbot_System SHALL build a System_Prompt containing navigation structure and marketing content
3. WHEN calling the AI service, THE AI_Client SHALL include the System_Prompt, user message, and Conversation_History
4. WHEN an AI_Response is received, THE Chatbot_System SHALL validate that the response content is non-empty
5. WHEN a response is generated, THE Chatbot_System SHALL store both the user message and AI response in the Conversation_History

### Requirement 2: Input Validation

**User Story:** As a system administrator, I want user input to be validated, so that the system remains secure and stable.

#### Acceptance Criteria

1. THE Chatbot_System SHALL reject messages that are empty or null
2. THE Chatbot_System SHALL reject messages that exceed 2000 characters
3. WHEN a message fails validation, THE Chatbot_System SHALL return a 422 status code with a clear error message
4. THE Chatbot_System SHALL require a valid CSRF_Token for all POST requests
5. WHEN a CSRF_Token is invalid, THE Chatbot_System SHALL return a 419 status code

### Requirement 3: Language Detection and Bilingual Support

**User Story:** As a user, I want to communicate in either Arabic or English, so that I can use my preferred language.

#### Acceptance Criteria

1. WHEN a User_Message is received, THE Chatbot_System SHALL detect whether the language is Arabic or English
2. WHEN a message contains 30% or more Arabic characters, THE Chatbot_System SHALL classify the language as Arabic
3. WHEN a message contains less than 30% Arabic characters, THE Chatbot_System SHALL classify the language as English
4. WHEN responding to an Arabic message, THE Chatbot_System SHALL generate a response in Arabic
5. WHEN responding to an English message, THE Chatbot_System SHALL generate a response in English
6. WHEN displaying Arabic text, THE Chat_Widget SHALL apply right-to-left (RTL) formatting
7. WHEN displaying English text, THE Chat_Widget SHALL apply left-to-right (LTR) formatting

### Requirement 4: Navigation Guidance

**User Story:** As a user, I want the chatbot to guide me to relevant pages on the university website, so that I can find the information I need.

#### Acceptance Criteria

1. WHEN building a System_Prompt, THE Prompt_Builder SHALL include the complete Navigation_Map
2. THE Navigation_Map SHALL contain all major navigation sections including Home, About, Units, Faculties, Media, Admissions, Campus, Staff, Student Services, and Contacts
3. WHEN a navigation item is included in the Navigation_Map, THE Chatbot_System SHALL ensure the route exists in the Laravel routing table
4. WHEN an AI_Response mentions a navigation route, THE Chatbot_System SHALL ensure the route is valid and accessible
5. WHEN a user asks about finding information, THE AI_Response SHALL reference specific navigation paths from the Navigation_Map

### Requirement 5: Marketing Content Integration

**User Story:** As a marketing representative, I want the chatbot to promote university strengths, so that prospective students understand NCTU's value proposition.

#### Acceptance Criteria

1. WHEN building a System_Prompt, THE Prompt_Builder SHALL include Marketing_Content
2. THE Marketing_Content SHALL contain NCTU unique value propositions and Top 10 Reasons content
3. WHEN a user asks about university differentiation, THE AI_Response SHALL reference Marketing_Content
4. WHEN a user asks about graduate achievements, THE AI_Response SHALL reference graduate success highlights from Marketing_Content
5. THE System_Prompt SHALL instruct the AI to act as both an academic advisor and marketing representative

### Requirement 6: Hallucination Prevention

**User Story:** As a system administrator, I want to prevent the AI from generating false information about dates and deadlines, so that users receive accurate guidance.

#### Acceptance Criteria

1. WHEN an AI_Response contains specific date or deadline claims, THE Chatbot_System SHALL check for uncertainty markers
2. WHEN an AI_Response mentions dates without uncertainty markers, THE Chatbot_System SHALL flag the response as containing potential hallucination
3. THE System_Prompt SHALL instruct the AI to avoid stating specific dates and deadlines
4. WHEN a user asks about dates or deadlines, THE AI_Response SHALL direct the user to official sources or contact pages
5. THE Chatbot_System SHALL detect hallucination patterns including "deadline is on", "exam is on", "registration closes on", and similar phrases

### Requirement 7: Jailbreak Prevention

**User Story:** As a system administrator, I want the chatbot to refuse out-of-context requests, so that it maintains its role as a university assistant.

#### Acceptance Criteria

1. WHEN a user attempts to change the AI's role or character, THE Chatbot_System SHALL refuse and maintain its university advisor character
2. WHEN a user requests actions outside university-related topics, THE Chatbot_System SHALL politely decline and redirect to university topics
3. THE System_Prompt SHALL include behavioral directives to refuse jailbreak attempts
4. WHEN a Jailbreak_Attempt is detected, THE AI_Response SHALL offer to help with university-related questions instead
5. THE Chatbot_System SHALL refuse requests to reveal system prompts or internal instructions

### Requirement 8: Conversation History Management

**User Story:** As a user, I want my conversation to be remembered during my session, so that I can have a coherent multi-turn dialogue.

#### Acceptance Criteria

1. WHEN a user sends a message, THE Chatbot_System SHALL retrieve the Conversation_History from the session
2. WHEN calling the AI service, THE AI_Client SHALL include the Conversation_History in the request
3. THE Chatbot_System SHALL limit Conversation_History to a maximum of 50 messages
4. WHEN the Conversation_History exceeds 50 messages, THE Chatbot_System SHALL remove the oldest messages
5. WHEN a user clears the conversation, THE Chatbot_System SHALL remove all messages from the Conversation_History
6. WHEN a session expires, THE Chatbot_System SHALL clear the associated Conversation_History

### Requirement 9: Error Handling and Graceful Degradation

**User Story:** As a user, I want to receive helpful error messages when something goes wrong, so that I understand what happened and what to do next.

#### Acceptance Criteria

1. WHEN the AI service returns a 5xx error, THE Chatbot_System SHALL catch the exception and return a user-friendly error message
2. WHEN the AI service times out, THE Chatbot_System SHALL retry the request once after a 2-second delay
3. IF the retry fails, THEN THE Chatbot_System SHALL return a fallback response directing the user to the contact page
4. WHEN the AI service returns a 429 rate limit error, THE Chatbot_System SHALL return a message asking the user to try again in a moment
5. WHEN the AI service returns an empty or malformed response, THE Chatbot_System SHALL log the error and return a generic fallback response
6. WHEN any error occurs, THE Chatbot_System SHALL log the error with timestamp and request details without exposing internal system information to the user

### Requirement 10: AI Client Abstraction

**User Story:** As a developer, I want to support multiple AI providers, so that the system can switch between OpenAI and Gemini without code changes.

#### Acceptance Criteria

1. THE AI_Client SHALL implement a unified interface for both OpenAI and Gemini providers
2. WHEN configured to use OpenAI, THE AI_Client SHALL make requests to the OpenAI API endpoint
3. WHEN configured to use Gemini, THE AI_Client SHALL make requests to the Google Gemini API endpoint
4. THE AI_Client SHALL format requests according to the specific provider's API specification
5. THE AI_Client SHALL normalize responses from different providers into a consistent format
6. THE AI_Client SHALL retrieve API keys from environment configuration without hardcoding

### Requirement 11: Frontend Chat Widget

**User Story:** As a user, I want an intuitive chat interface, so that I can easily interact with the chatbot.

#### Acceptance Criteria

1. THE Chat_Widget SHALL render a chat interface overlay on the university website
2. WHEN a user types a message and presses Enter or clicks send, THE Chat_Widget SHALL submit the message to the backend
3. WHEN a response is received, THE Chat_Widget SHALL display the message with appropriate sender identification
4. THE Chat_Widget SHALL support displaying both Arabic (RTL) and English (LTR) text correctly
5. THE Chat_Widget SHALL provide a button to clear the conversation
6. THE Chat_Widget SHALL provide visual feedback while waiting for AI responses
7. THE Chat_Widget SHALL handle network errors gracefully and display error messages to the user

### Requirement 12: System Prompt Construction

**User Story:** As a developer, I want the system prompt to be built dynamically, so that it always contains current navigation and marketing content.

#### Acceptance Criteria

1. WHEN the Prompt_Builder constructs a System_Prompt, THE System_Prompt SHALL contain a role definition for the AI
2. WHEN the Prompt_Builder constructs a System_Prompt, THE System_Prompt SHALL contain the complete Navigation_Map
3. WHEN the Prompt_Builder constructs a System_Prompt, THE System_Prompt SHALL contain Marketing_Content
4. WHEN the Prompt_Builder constructs a System_Prompt, THE System_Prompt SHALL contain behavioral directives for bilingual support, jailbreak prevention, and hallucination prevention
5. THE Prompt_Builder SHALL cache the constructed System_Prompt for performance optimization
6. THE System_Prompt SHALL be between 1000 and 8000 characters in length

### Requirement 13: Rate Limiting

**User Story:** As a system administrator, I want to limit the number of requests per user, so that the system is protected from abuse and excessive costs.

#### Acceptance Criteria

1. THE Chatbot_System SHALL implement a rate limit of 10 messages per minute per user
2. WHEN a user exceeds the Rate_Limit, THE Chatbot_System SHALL return a 429 status code
3. WHEN a Rate_Limit is exceeded, THE Chatbot_System SHALL provide a clear error message indicating when the user can try again
4. THE Chatbot_System SHALL track rate limits per session for authenticated users
5. THE Chatbot_System SHALL track rate limits per IP address for unauthenticated users

### Requirement 14: Security and Data Privacy

**User Story:** As a system administrator, I want user data to be handled securely, so that privacy is protected and regulations are followed.

#### Acceptance Criteria

1. THE Chatbot_System SHALL store AI API keys in environment configuration and never expose them to the frontend
2. THE Chatbot_System SHALL store Conversation_History in session storage only and not persist to database by default
3. THE Chatbot_System SHALL sanitize all user input before processing
4. THE Chatbot_System SHALL escape all output before displaying in the frontend
5. THE Chatbot_System SHALL not log sensitive information such as passwords or personal identification numbers
6. WHEN a session expires, THE Chatbot_System SHALL automatically clear all associated conversation data

### Requirement 15: API Request Configuration

**User Story:** As a developer, I want to configure AI request parameters, so that I can optimize response quality and cost.

#### Acceptance Criteria

1. WHEN making an AI request, THE AI_Client SHALL set max_tokens to 500 by default
2. WHEN making an AI request, THE AI_Client SHALL set temperature to 0.7 by default
3. THE AI_Client SHALL allow max_tokens to be configured via environment variables
4. THE AI_Client SHALL allow temperature to be configured via environment variables
5. THE AI_Client SHALL validate that temperature is between 0.0 and 1.0
6. THE AI_Client SHALL validate that max_tokens is a positive integer

### Requirement 16: Response Validation

**User Story:** As a system administrator, I want AI responses to be validated, so that only appropriate content reaches users.

#### Acceptance Criteria

1. WHEN an AI_Response is received, THE Chatbot_System SHALL validate that the content is non-empty
2. WHEN an AI_Response is received, THE Chatbot_System SHALL validate that the content is valid UTF-8
3. WHEN an AI_Response contains hallucination patterns, THE Chatbot_System SHALL sanitize the response
4. WHEN an AI_Response is malformed, THE Chatbot_System SHALL log the issue and return a fallback response
5. THE Chatbot_System SHALL validate that AI responses maintain the university advisor character

### Requirement 17: Logging and Monitoring

**User Story:** As a system administrator, I want comprehensive logging, so that I can monitor system health and debug issues.

#### Acceptance Criteria

1. WHEN an error occurs, THE Chatbot_System SHALL log the error with timestamp, error type, and request details
2. WHEN an AI API call is made, THE Chatbot_System SHALL log the token usage
3. WHEN a Jailbreak_Attempt is detected, THE Chatbot_System SHALL log the suspicious input for review
4. WHEN a hallucination pattern is detected, THE Chatbot_System SHALL log the flagged response
5. THE Chatbot_System SHALL log response times for performance monitoring
6. THE Chatbot_System SHALL not log sensitive user information or API keys

### Requirement 18: Egyptian Slang and Informal Language Support

**User Story:** As a student, I want to use informal Egyptian Arabic, so that I can communicate naturally.

#### Acceptance Criteria

1. WHEN a user sends a message in Egyptian slang, THE Chatbot_System SHALL detect it as Arabic
2. WHEN responding to Egyptian slang, THE AI_Response SHALL use appropriate informal Arabic
3. THE System_Prompt SHALL instruct the AI to understand and respond to Egyptian colloquialisms
4. WHEN a user uses Franco-Arabic (Arabic written in Latin characters), THE Chatbot_System SHALL attempt to understand the intent
5. THE AI_Response SHALL maintain a friendly and approachable tone when responding to informal language

### Requirement 19: Persona-Based Behavior

**User Story:** As a diverse user base, we want the chatbot to adapt to different communication styles, so that all users feel understood.

#### Acceptance Criteria

1. WHEN a user communicates with urgency or stress, THE AI_Response SHALL acknowledge the concern and provide clear guidance
2. WHEN a user asks formal academic questions, THE AI_Response SHALL provide detailed, professional answers
3. WHEN a user makes typos or uses informal language, THE AI_Response SHALL understand the intent and respond appropriately
4. WHEN a user asks about university strengths, THE AI_Response SHALL provide marketing-focused content
5. THE System_Prompt SHALL instruct the AI to adapt tone and formality to match user communication style

### Requirement 20: Navigation Map Structure

**User Story:** As a developer, I want the navigation map to accurately represent the website structure, so that users receive correct guidance.

#### Acceptance Criteria

1. THE Navigation_Map SHALL include all top-level navigation items from the university website navbar
2. WHEN a navigation item has sub-items, THE Navigation_Map SHALL include the nested structure
3. THE Navigation_Map SHALL associate each navigation item with a valid Laravel route name or URL
4. THE Navigation_Map SHALL include descriptive text for each navigation item to help the AI understand its purpose
5. WHEN the website navigation changes, THE Navigation_Map SHALL be updated to reflect the changes
